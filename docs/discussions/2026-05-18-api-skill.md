# /api skill v1

## 議題定義

### 背景

Phase 1.e 已完成：Genesis bootstrap 產出可 build 的 Swift DDD/ES 專案骨架，含 `Sources/{A}Aggregate/{Entity, Usecase/Port, Usecase/Service}/`。**Adapter/ 仍為空 dir**（Genesis 不生成 HTTP 層邏輯）。`/api` skill 是補上 HTTP 適配層的 per-UC 工具。

OC 為 ground truth（per Phase 1.e 既有原則）。Gemini facts report 跨讀 `/Users/abnertsai/JiaBao/Mendesky/OpportunityContext/Sources/AuditQuotingAggregate/Adapter/`，揭示 OC 的 canonical pattern：

- 每 UC 一個 `Adapter/<UC>/<UC>ApplicationService.swift`（單檔 ~97 LoC，含 Input + Output + ApplicationService struct + payload→Input init extension）
- 整 aggregate **一個** `Adapter/ApiHandler.swift`（OC 1524 行、24 endpoint method 全在一檔；刻意 repetitive，不抽 helper）
- Cross-UC side effect：新 domain error 引入時必須更新 `Adapter/ApiComponents/ApiComponents+<Ctx>ApiError.swift` 的 exhaustive switch（compiler-enforced）

### 目標

寫出 `~/.claude/skills/api/SKILL.md` v1 的真實內容（取代當前 9 行 placeholder），實作 `/api <UC>` 一次處理一個 UC，per D18 硬限制（200 LoC SKILL.md / 6 steps / 一 UC per invocation / 不讀 invariants.md / 不寫 openapi.yaml）。

完成後在 `/tmp/phase1e-manual` 跑一次 `/api createUserAccessProfile` 驗證能 generate 正確的 ApplicationService + 修補 ApiHandler.swift。

### 範圍

#### 討論內（in scope for v1）

- v1 寫 `Adapter/<UC>/<UC>ApplicationService.swift`（含 3 個 declaration）
- v1 寫 optional `Adapter/<UC>/<UC>Dto.swift`（當 OpenAPI request body 含 nested enum / discriminated union）
- v1 **附加** method 到既有 `Adapter/ApiHandler.swift`（首次跑時若檔不存在則先 create skeleton）
- v1 **更新** `Adapter/ApiComponents/ApiComponents+<Ctx>ApiError.swift` 的 switch（新 domain error 時）
- v1 讀 `api.md` 拿 error→HTTP mapping、`openapi.yaml` 拿 endpoint signature、`Usecase/Service/<UC>Service.swift` 拿 Input/Output shape、ApiHandler.swift 現狀

#### 討論外（Non-goals for v1）

- **不**支援 read UCs（kdbClient: 注入而非 repository:）— v2 / `/api-query`
- **不**支援 multipart upload UCs（不同 handler shape）— v2
- **不**寫 `Tests/.../Api/<UC>/` 測試（test scaffolding 留 separate skill 或 user）
- **不**寫 `openapi.yaml`（per D18）；spec 寫作期 `/api` 假設 openapi.yaml 已存在
- **不**讀 `invariants.md`（per D18）
- **不**抽 ApiHandler.swift 的 helper / refactor（per OC api.md「刻意保留」）
- **不**生成 OCServer.swift 或 routing wire-up（user 自行串）
- **不**做 Decimal 等 numeric parsing 邏輯具體實作（emit TODO stub）
- **不**處理 Cosmogony bundle / Genesis 那層的 codegen — 那是 Phase 1 範圍

### 約束

1. **D18 hard limits**：≤ 200 LoC SKILL.md、6 steps（無例外）、only writes `Adapter/` subtree、never reads `invariants.md`、never writes `openapi.yaml`、one UC per invocation
2. **OC 為 ground truth**：所有 code shape 對齊 OC `AuditQuotingAggregate/Adapter/` 慣例
3. **api.md 為 SSOT for error→HTTP**（D17）— skill 必讀；缺則 fail-fast
4. **package access modifier**：所有 generated code 皆 `package`（per OC + Genesis 既有慣例）

## 決策紀錄

### Decision 1: 6 個 step 的內容

**已 lock**

| Step | 動作 | 讀 / 寫 |
|---|---|---|
| 1 | Parse args (`<UC>`) + locate workspace | read: pwd / git root |
| 2 | Validate prerequisites | read: `api.md`、`openapi.yaml`、`Usecase/Service/<UC>Service.swift`；fail-fast if 缺 |
| 3 | Generate `Adapter/<UC>/<UC>ApplicationService.swift` | write |
| 4 | Generate optional `Adapter/<UC>/<X>Dto.swift`（nested enum / discriminated union 時）| write (conditional) |
| 5 | Append handler method to `Adapter/ApiHandler.swift`（first run create skeleton）| write/append |
| 6 | Update `Adapter/ApiComponents/ApiComponents+<Ctx>ApiError.swift` 的 switch | write (conditional：only if new domain error case 在此 UC 引入) |

### Decision 2: ApplicationService.swift 結構（對齊 OC）

**已 lock**：單檔 3 個 declaration —
- `package struct <UC>ApplicationServiceInput`（API 輸入 shape；不含 server-generated IDs）
- `package struct <UC>ApplicationServiceOutput`（API 輸出 shape）
- `package struct <UC>ApplicationService: ApplicationService`（重點 method `execute(input:)`）
- extension on Input：`init(from payload: Components.Schemas.<UC>Request, <aggregateId>: String, operatorId: String) throws`（OpenAPI 型別 → AS 輸入；ISO8601 等 throws 在這裡）

### Decision 3: ApiHandler.swift append pattern

**已 lock**：

- 若檔不存在：生成 skeleton（`struct ApiHandler<Storage: ...>: APIProtocol`、`private let kdbClient`、`private var repository: <A>Repository {...}`、`private func mapToApiError`）
- 已存在：在最後 `}` 前插入新 handler method（per OC 慣例每 method 5-15 LoC 含 guard + catch 階梯）
- handler method 結構：
  ```swift
  package func <ucCamel>(_ input: Operations.<ucCamel>.Input) async throws -> Operations.<ucCamel>.Output {
      guard case let .json(payload) = input.body else {
          return .unprocessableContent(.init(body: .json(.init(error: .invalidPayload))))
      }
      let asInput: <UC>ApplicationServiceInput
      do {
          asInput = try <UC>ApplicationServiceInput(
              from: payload,
              <aggregateId>: input.path.<aggregateId>,
              operatorId: input.headers.operatorId
          )
      } catch is Iso8601ParsingError {
          return .unprocessableContent(.init(body: .json(.init(error: .invalidDateFormat))))
      }
      let service = <UC>ApplicationService(repository: repository)
      do {
          let output = try await service.execute(input: asInput)
          return .ok(.init(body: .json(.init(<output fields>))))
      } catch let error as DDDError where error.code == .aggregateNotFound {
          return .notFound(.init(body: .json(.init(error: .aggregateNotFound))))
      } catch {
          if let apiError = mapToApiError(error) {
              return .unprocessableContent(.init(body: .json(.init(error: apiError))))
          }
          return .serviceUnavailable(.init(body: .json(.init(error: .serviceUnavailable))))
      }
  }
  ```
- 每 handler 4-7 catch branch 雷同；**刻意 repetitive**，不抽 helper（per OC api.md `ApiHandler 重複碼：刻意保留`）

### Decision 4: ApiError exhaustive switch 更新

**已 lock**

- skill 偵測：當前 UC 的 `<UC>Service.swift` 拋了哪些 `<A>Error.<case>` (grep)，比對 `ApiComponents+<Ctx>ApiError.swift` switch 是否已含
- 若有新 case：在 switch 中加 `case .<newCase>: self = .<newCase> // TODO: confirm trigger`（per facts report 「ambiguous trigger 留 TODO，不 silently `return nil`」）
- 對應地在 `openapi.yaml` 的 ApiError enum 必須有對應 case；若沒有 → skill 顯式 fail-fast 並列印「請先在 openapi.yaml 加 <case>，本 skill 不寫 openapi.yaml」
- D18 約束：**skill 不寫 openapi.yaml**；只更新 `ApiComponents+<Ctx>ApiError.swift`

### Decision 5: Read UCs / multipart upload 排除

**已 lock**：v1 不支援。skill 偵測：
- read UC 偵測：UC 名 prefix `get` / `list` / `find` → skill 顯式 fail with「v1 不支援 read UCs；待 `/api-query` 或 v2」
- multipart 偵測：openapi.yaml 中 endpoint 的 requestBody content type 含 `multipart/form-data` → skill 顯式 fail
- 維持 v1 scope cleanliness；明確 fail-fast 而非 silently 產半生不熟的 code

### Decision 6: api.md fail-fast

**已 lock**

- skill 第一個檢查就是 `.ai/contexts/<Ctx>/api.md` 是否存在、是否含 `## Response 慣例` 或等價表（HTTP status mapping）
- 缺則 skill exit 1 提示「請先補 `.ai/contexts/<Ctx>/api.md`；本 skill 不為你寫 transport conventions」（per D17）

### Decision 7: package access modifier

**已 lock**：所有 generated declarations 用 `package`（OC 慣例 + Genesis 既有所有 codegen 統一）；private 僅限 ApiHandler 內 stored properties（`kdbClient` / `storage`）

## 開放問題（spec 寫作期 step 3b 確認）

1. **OpenAPI Generator plugin 命名**：OC 用 `swift-openapi-generator` 在 `Package.swift` 加 `.plugin(name: "OpenAPIGenerator", package: "swift-openapi-generator")`。Genesis 目前**不**在 `PackageTarget.swift.template` 加此 plugin（只加 DomainEventGeneratorPlugin + ModelGeneratorPlugin）。問題：`/api` skill 是否要負責提醒 user 加？或假設 user 早已加？建議：v1 假設 user 已加，spec 中明示「prerequisite」並提示具體 commands。
2. **`Adapter/ApiHandler.swift` first-run skeleton 形狀**：OC 的 ApiHandler 有 `<Storage: StorageProtocol & Sendable>` generic（為 multipart 用），但 multipart 在 v1 排除。skeleton 是否需 generic？建議：v1 不生 generic（最小可行），multipart 加入時再 revise。
3. **`<UC>Service.swift` 介面合約推導**：skill 從 Service 檔讀 `Input` / `Output` 結構（per Phase 1.e 產出）。問題：如 user 已手動改了 Service（加新欄位），skill 要忠實鏡像當前 Service 還是回頭看 openapi.yaml？建議：以 `<UC>Service.swift` 為 SSOT；openapi.yaml 為 outer-edge 對齊，二者不一致時 fail-fast 並列出 diff，由 user 決定如何修正。
4. **AS init 的 throws 範圍**：facts report 揭示「ISO8601 parsing 在 AS init throws；Decimal parsing 在 handler edge」。v1 是否要識別 field type → 自動選 parse 位置？建議：v1 一律生 stub 用 `try` 在 AS init，Decimal/UUID 等 type 加註解 `// GENESIS-STUB: consider moving parse to handler if user-facing parse error needed`，user 自行調整。
5. **第一個 UC 的 ApiComponents+<Ctx>ApiError.swift 是否存在**：Genesis Phase 1 不產此檔。/api 第一次 invocation 須 create 它（內含 `import OCShared` + `extension Components.Schemas.<Ctx>ApiError` 結構 + 第一條 case）。建議：v1 spec 寫明「首次跑時 create skeleton」、後續 invocation 「append case」。
6. **Cross-context 共用 convention**：facts report 提 `.ai/conventions/api.md` cross-context shared。Genesis Phase 1.c 已 bootstrap `.ai/conventions/api.md`（per `ContextLevelRenderer`）— 本 skill 是否要讀 conventions/api.md 來合併 per-Ctx api.md？建議：v1 只讀 per-Ctx `api.md`（D17 明示 SSOT），conventions/ 留 v2。
