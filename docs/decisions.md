## Genesis-specific revisions to D-decisions

The Genesis framing (CLI as standalone tool independent of DDDKit, with install-time MCP opt-in) revises two earlier decisions:

- **D29 (CanvasMCP.swift wrapper)** — was scoped to Genesis CLI. Under new framing, Genesis does NOT call MCP. The adapter wrapper lives in the Claude Code skill that does `apply-canvas-ops`, not in Genesis.
- **D31 (sync is CLI not skill)** — was a single rule. Under new framing, split: `plan-canvas-sync` stays in CLI (no MCP), `apply-canvas-ops` moves to skill (uses MCP).

Both revisions follow from the Genesis vision clarified by user on 2026-05-13: "MCP is install-time opt-in; the CLI writes MCP config but doesn't talk MCP itself."
