### Internal module：`GenesisCore.CaseTransformer`（新）

```swift
public enum CaseTransformer {
```

### Internal module：`GenesisCore.SourceWriter`（新）

```swift
public final class SourceWriter {
    public init(root: URL)

    /// Queue a file write (no fs mutation yet).
    public func plan(relativePath: String, content: String)

    /// Atomically write all planned files. On any failure, automatically rolls back.
    public func commit() throws

    /// Manual rollback — caller invokes from outer catch (e.g. swift build 失敗時).
    public func rollback()
}
```

**行為**：
- `plan` 純記憶體 append；可被無數次呼叫
- `commit` 依序：
  1. 對每個 planned file，**逐層**檢查 parent dirs（從 root 起，每一級都 check 是否 fs exists）— 收集**所有本次需要新建的層級**到 `createdDirs`（**從淺到深順序**插入）
  2. 對該檔的 parent 跑 `createDirectory(... withIntermediateDirectories: true)` 一次建好整條
  3. Atomically write 該檔；append 到 `writtenFiles`
  4. 任一步失敗，**立即** invoke `rollback()` 並 rethrow `GenesisError.fileSystemFailed(...)`
- `rollback` 行為：
  - 從 `writtenFiles` **反序**逐個刪除每個檔案（`FileManager.removeItem`）
  - 從 `createdDirs` **反序**（最深的先試）逐個檢查：若該 dir 仍為空，刪；若已被外部寫入內容（含 .DS_Store 等），保留
  - 兩者用 `try?` 包：rollback 不該 throw（否則會掩蓋原始 error）
- 不處理 git；rollback 完只清 fs，git 狀態回到 commit 前

🔴 **`createdDirs` 必須逐層追蹤**（codex 點出陷阱：若 caller 一次 plan 到 `Sources/UserAccessProfileAggregate/Entity/Commands/foo.swift`，且 `Sources/` 本來不存在，rollback 必須同時刪除 `Sources/`、`Sources/UserAccessProfileAggregate/`、`...Entity/`、`...Commands/` 四層。`createDirectory(... withIntermediateDirectories: true)` 一次建好，但 `createdDirs` 追蹤必須細到每一層，否則 rollback 會留下空目錄）。實作建議：

```swift
private func recordCreatedParents(for fileURL: URL) {
    var ancestors: [URL] = []
    var cursor = fileURL.deletingLastPathComponent()
    while cursor != root && cursor.path != "/" {
        if !FileManager.default.fileExists(atPath: cursor.path) {
            ancestors.append(cursor)
        } else {
            break  // 此層已存在，更上層必然也存在
        }
        cursor = cursor.deletingLastPathComponent()
    }
    // ancestors 從深到淺，先插入到 createdDirs（rollback 時又會 reverse 一次回到深→淺刪除順序）
    createdDirs.append(contentsOf: ancestors.reversed())  // 變成淺→深記錄
}
```

🔴 **所有權明示**：`SourceWriter` 只負責多檔案 atomic 寫入 + rollback。**Git rollback 不在此處**；`NewCommand` 已負責 dir-level rollback（Phase 1.a Step 6.15）。Phase 1.b 加入後，rollback 鏈：SourceWriter.rollback → NewCommand outer catch → 若 `dirCreatedByThisRun` 且空 → 刪 dir。

🔴 **CreatedEventType 怎麼挑**（codex 質疑 hardcoded 太 schema-dependent，已加 fallback 鏈）：

每個 aggregate 必須恰好有一個 use case 的 emittedEvent 在 bundle 中表示「created」事件。**Genesis 啟發式 fallback 鏈**（按優先順序試）：

1. **首選**：找 `useCase == "create" + UpperCamel(aggregate.name)`（如 `createUserAccessProfile`）
2. **fallback 1**：找 `emittedEvent` 名稱以 `Created` 結尾（如 `userAccessProfileCreated`、`accountCreated`）的 useCase
3. **fallback 2**：找 `useCase` 名稱開頭是 `register` / `bootstrap` / `open` / `init` 其中之一的 useCase
4. **若全部 fallback 都找不到 → throw**：
   ```
   bundleInvalid(reason: "cannot identify Created use case for aggregate '\(name)'. Tried:
     1. useCase == 'create\(name)'
     2. emittedEvent ending in 'Created'
   ```

#### Aggregate.swift.template（新）— 對齊 DDDKit canonical TestAggregateRoot

🔴 **重大設計修正**（codex 外部審查 + 實證 `Tests/DDDCoreTests/DDDCoreTests.swift` 的 `class TestAggregateRoot`）：原 spec 把 state 全塞 designated init 是 anti-pattern。**event-sourcing canonical 模式**是 designated init 只接 `id`、state 全部 `Optional`、bootstrap 時 `apply(event:)` 經 `when(happened:)` dispatch 到 typed overload 填回 state。本 template 改為遵循 canonical：

```swift
import DDDKit
import Foundation

package final class {Aggregate}: AggregateRoot {
    package typealias ID = String
    package typealias CreatedEventType = {CreatedEventTypeName}
    package typealias DeletedEventType = {Aggregate}Deleted

    package var id: String
    package var metadata: AggregateRootMetadata = .init()

    // State (Optional; populated by applying Created event via `when(happened:)` → typed `when(event:)` overloads in
    // Entity/Commands/{Aggregate}+<UC>.swift). Downstream `/usecase` skill may tighten to non-optional once
    // business rules clarify which fields are always set.
{StateFieldDecls}

    package init(id: String) {
        self.id = id
        // GENESIS-STUB: caller builds {CreatedEventTypeName} with whatever payload it needs, then
        //   try? apply(event: createdEvent)
        // The Created event will flow through `when(happened:)` → `when(event: {CreatedEventTypeName})`
        // (in Entity/Commands/...) and populate state.
    }

    package required convenience init?(first firstEvent: CreatedEventType, other events: [any DomainEvent]) throws {
        self.init(id: firstEvent.aggregateRootId)
        try apply(events: [firstEvent] + events)
    }

    package func when(happened event: some DomainEvent) throws {
        // Dispatch to typed overloads defined in Entity/Commands/{Aggregate}+<UC>.swift.
        // If a new event type is added but the switch is not extended, the aggregate silently ignores it.
        switch event {
{EventDispatchCases}
        default:
            // GENESIS-STUB: replace `break` with `throw {Aggregate}Error.unhandledEvent` once the enum has the case.
            break
        }
    }

    package func ensureInvariant() throws {
        // GENESIS-STUB: validate {Aggregate} invariants. See {Aggregate}Error for codes (e.g.
        // throw {Aggregate}Error.userIdNotExist if self.userId == nil).
    }
}
```

**Caller 端要組的變數**：
- `{Aggregate}` — aggregate.name
- `{CreatedEventTypeName}` — `upperCamel(createUseCase.emittedEvent)`，由 §「CreatedEventType 怎麼挑」決定
- `{StateFieldDecls}` — 每個 `state[i]` 一行 `    package var {name}: {resolvedType}?`（**注意 Optional 後綴 `?`**），join `\n`。**所有 state 一律 Optional**。
- `{EventDispatchCases}` — 對該 aggregate 的每個 event 一行：
  ```
          case let e as {EventTypeName}: try when(event: e)
  ```
  其中 `{EventTypeName} = upperCamel(eventName)`，含 createdEvent / deletedEvent / domainEvent 全部
  - 若 aggregate 有 7 個 events，這裡就會有 7 個 case + 自動補的 `{Aggregate}Deleted` 一個 case，共 8 個 case

🔴 **canonical 模式的好處**：
- `init(id:)` 簡單，符合 DDDKit `TestAggregateRoot` 範本
- `init?(first:other:)` 自動把 createdEvent 跟其他 events 一起 re-apply（`[firstEvent] + events`），不需 user 額外想怎麼從 firstEvent 萃取 state
- `when(happened:)` 自動 dispatch 到 typed overload — 用 `Entity/Commands/...` 內的 `when(event: SpecificType)` 來填 state，user 只需在 typed overload 內寫 1 行 `self.someField = event.somePayload`

### Step 3：SwiftTypeResolver

```swift
public static func resolve(rawType: String, knownCustomTypes: Set<String>) throws -> String {
    let trimmed = rawType.trimmingCharacters(in: .whitespaces)

    // 3.1 primitives（identity）
    let primitives: Set<String> = ["String", "Int", "Bool", "Decimal", "Date", "UUID", "Float", "Double"]
    if primitives.contains(trimmed) { return trimmed }

    // 3.2 Array[X] → [X]
    if let m = trimmed.firstMatch(of: /^Array\[(.+)\]$/) {
        let inner = String(m.1)
        return "[" + (try resolve(rawType: inner, knownCustomTypes: knownCustomTypes)) + "]"
    }

    // 3.3 Set<X> → Set<X>（identity 但要遞迴驗 inner）
    if let m = trimmed.firstMatch(of: /^Set<(.+)>$/) {
        let inner = String(m.1)
        _ = try resolve(rawType: inner, knownCustomTypes: knownCustomTypes)
        return trimmed
    }

    // 3.4 known custom type
    if knownCustomTypes.contains(trimmed) { return trimmed }

    // 3.5 reject
    throw GenesisError.bundleInvalid(reason: "unknown type '\(rawType)' — not a primitive, container, or known DTO")
}
```

### Step 5：SourceWriter

```swift
public final class SourceWriter {
    public let root: URL
    private var planned: [(URL, String)] = []
    private var writtenFiles: [URL] = []
    private var createdDirs: [URL] = []

    public func plan(relativePath: String, content: String) {
        let url = root.appendingPathComponent(relativePath)
        planned.append((url, content))
    }

    public func commit() throws {
        for (url, content) in planned {
            let parent = url.deletingLastPathComponent()
            // Track newly-created dirs for rollback
            let alreadyExisted = FileManager.default.fileExists(atPath: parent.path)
            do {
                try FileManager.default.createDirectory(at: parent, withIntermediateDirectories: true)
            } catch {
                rollback()
                throw GenesisError.fileSystemFailed(operation: "create directory \(parent.path)", underlying: error.localizedDescription)
            }
            if !alreadyExisted {
                createdDirs.append(parent)  // for later rollback
            }

            do {
                try content.write(to: url, atomically: true, encoding: .utf8)
                writtenFiles.append(url)
            } catch {
                rollback()
                throw GenesisError.fileSystemFailed(operation: "write file \(url.path)", underlying: error.localizedDescription)
            }
        }
    }

    public func rollback() {
        for url in writtenFiles.reversed() {
            try? FileManager.default.removeItem(at: url)
        }
        // Delete created dirs only if empty (from deepest to shallowest)
        for dir in createdDirs.reversed() {
            let contents = (try? FileManager.default.contentsOfDirectory(atPath: dir.path)) ?? []
            if contents.isEmpty {
                try? FileManager.default.removeItem(at: dir)
            }
        }
        writtenFiles.removeAll()
        createdDirs.removeAll()
    }
}
```

## 已知限制

- **Storage coordinator 預設 ESDB**（codex 確認 DDDKit 1.12.4 公開 `ESDBStorageCoordinator`；`KurrentStorageCoordinator` 不存在於該版本）。Phase 1.c 的 `swift-adapter.yaml` 可改 coordinator（如未來 DDDKit 釋出 Kurrent variant 後）。 <!-- ⚠️ superseded by `dddkit-correction`: 此結論依據讀錯的 Mendesky/DDDKit。gradyzhuo/swift-ddd-kit 0.3.0 已內建 `KurrentStorageCoordinator<StreamNaming>` 於 `KurrentSupport` target，當前預設改為 Kurrent -->
- **AggregateRoot.ID 一律 String**（Phase 0 決議；技術上 DDDKit 只要求 Hashable）— typed ID wrapper 須走 Phase 1.c adapter
- **State fields 一律 Optional `?`**（canonical event-sourcing 模式）：state 不在 designated init 設定，而是在 `when(event:)` 內由 event payload 填回。Optional 是「nil = 尚未 hydrate」的明確標記。Phase 1.c `/usecase` skill 可選擇性收窄為非 Optional（需要 hydrate-on-init 約定）。
- **CommandExtension 參數含所有 useCase.input 欄位**（含 `userId` 等通常該由 service 注入的）— user 後續精簡
- **DTO 都掛第一個 aggregate target 下**（簡化，避免引入 Shared target）— **若兩個 aggregates 同時 reference 同一個 DTO，第二個 aggregate 的 target 會 "cannot find type 'XYZ'"，swift build 失敗**。Phase 1.b sample（IAM bundle 只有單一 aggregate）不會觸發；多 aggregate bundle 須等 Phase 1.c 引入 `Sources/{Context}Shared/` target 後才支援
- **DTO enum / struct 判定靠 description heuristic**（含 "enum"/"Enum" → enum）— 脆弱；upstream Cosmogony 加 `kind` 欄位可解決
- **DeletedEvent 自動補**：每個 aggregate 自動補 `{Aggregate}Deleted` event（kind: deletedEvent，properties 只有 aggregateRootId）；user 後續若要客製化（如 OC 的 `aggregateRoot2Id` 雙 key）需手改 event.yaml
- **`event-generator-config.yaml.template` 是固定內容**（`accessModifier: package` 一行）— 不支援自訂 dependencies / aggregateRootName，Phase 1.c adapter 可加
- **`when(happened:)` switch 預設 ignore unknown event**（`default: break`）；若有 strict mode 需求（unknown event 應 throw），須在 `{Aggregate}Error.swift` 加 `case unhandledEvent` 並改 switch default branch
- **`when(event:)` typed overload 預設 empty body**（不是 fatalError），因為它在 replay 期就會被呼叫；fatalError 會讓 replay 死。User/AI 需在裡面填 `self.foo = event.foo` 一行 ditto per state field
- **CreatedEventType 啟發式三層 fallback**：`create{Aggregate}` → `*Created` 後綴 → `register/bootstrap/open/init` 前綴。若三者都不命中，throw 含具體錯誤。Phase 1.c 加 swift-adapter.yaml override 後此 hardcoded 邏輯可移除
- **Multi-context 不支援**：Phase 1.b 一個 bundle 對應一個 context。Phase 4 才考慮 multi-context 同步
