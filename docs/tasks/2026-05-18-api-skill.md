### TODO fill category 1: ApplicationService `execute()` body

**Before** (Phase 1.h scaffold)：
```swift
    package func execute(input: Input) async throws -> Output {
        // TODO(/api skill): construct {UC}Service Input from `input` and call service.execute
        fatalError("TODO(/api skill): execute body for {UC}ApplicationService")
    }
```

**After fill (Variant A simple, no UUID generation)**：
```swift
    package func execute(input: Input) async throws -> Output {
        let service = {UC}Service(repository: repository)
        _ = try await service.execute(input: .init(
            {AGG_ID_NAME}: input.{AGG_ID_NAME},
{SERVICE_INPUT_FIELDS_FROM_AS}
            operatorId: input.operatorId
        ))
        return .init({AGG_ID_NAME}: input.{AGG_ID_NAME})
    }
```

`{SERVICE_INPUT_FIELDS_FROM_AS}`: 每 non-ID non-operatorId AS Input field → `            <name>: input.<name>,`

**Variant with server-generated ID**（detected when Service Input has ID field but AS Input doesn't）：
```swift
    package func execute(input: Input) async throws -> Output {
        let {ID_FIELD} = UUID().uuidString
        let service = {UC}Service(repository: repository)
        _ = try await service.execute(input: .init(
            {AGG_ID_NAME}: input.{AGG_ID_NAME},
            {ID_FIELD}: {ID_FIELD},
{OTHER_FIELDS}
            operatorId: input.operatorId
        ))
        return .init({AGG_ID_NAME}: input.{AGG_ID_NAME})
    }
```

> **audit H3**：generated `{ID_FIELD}` **只**傳進 Service Input，**不**進 AS Output。Phase 1.h `ApplicationServiceOutput` scaffold 只有 aggregate id field，scope 又禁止改 type signature——所以 `return .init(...)` 必須維持 `.init({AGG_ID_NAME}: input.{AGG_ID_NAME})` 不變。若 API 確實要回傳新 child id，屬另開 Phase 改 scaffold/openapi/handler response 的工作，不在本填空 scope。

Detection rule (skill 內 logic)：parse Service.swift Input fields；diff with AS Input fields；若 Service Input 有 field 是 `String` 且名為 `*Id` (suffix `Id`，比對前 lowercased) 且 AS Input 無此 field → server-generated case.

### TODO fill category 2: ApiHandler method AS Input construction

**Before** (Phase 1.i scaffold)：
```swift
    package func {ucCamel}(_ input: Operations.{ucCamel}.Input) async throws -> Operations.{ucCamel}.Output {
        guard case let .json(payload) = input.body else {
            return .unprocessableContent(.init(body: .json(.init(error: .invalidPayload))))
        }
        let {aggIdName} = input.path.{aggIdName}
        let operatorId = input.headers.operatorId
        _ = payload
        _ = {aggIdName}
        _ = operatorId

        // TODO(/api skill): construct AS Input from `payload`, `{aggIdName}`, `operatorId`.
        let asInput: {UC}ApplicationServiceInput = { () -> {UC}ApplicationServiceInput in
            fatalError("TODO(/api skill): construct {UC}ApplicationServiceInput from payload")
        }()
        ...
```

**After fill (Variant A simple — payload fields 1:1 pass)**:
```swift
        let asInput = {UC}ApplicationServiceInput(
            {aggIdName}: {aggIdName},
{PAYLOAD_FIELDS_PASS_THROUGH}
            operatorId: operatorId
        )
```

**Variant B detection (audit H2 — 以 AS Input 欄位型別為 truth，不看 openapi schema)**：
Phase 1.i 把 Decimal/Date 都 emit 成 plain `type: string`（無 pattern/format），所以**不能**靠 openapi schema 判斷。判定來源 = **AS Input field 的 Swift 型別**（從 `<UC>ApplicationService.swift` 的 Input struct 解析）：

| AS Input field target type | 填法 |
|---|---|
| `Decimal` | `Decimal(string: payload.<f>)` guard，失敗回 422（error case 見下方 H4 規則） |
| `Date` | `try Date.parseIso8601(payload.<f>)`，catch `Iso8601ParsingError` → `.invalidDateFormat` |
| `String` / 其他 plain | pass-through `payload.<f>` |

openapi schema 只用來確認 payload **欄位存在**，不決定型別轉換。

```swift
        guard let estimatedRevenue = Decimal(string: payload.estimatedRevenue) else {
            return .unprocessableContent(.init(body: .json(.init(error: {DECIMAL_ERROR_CASE}))))
        }
        let asInput = {UC}ApplicationServiceInput(
            {aggIdName}: {aggIdName},
            estimatedRevenue: estimatedRevenue,
{OTHER_FIELDS}
            operatorId: operatorId
        )
```

> **audit H4 — Decimal parse error case 解析**：`{DECIMAL_ERROR_CASE}` 不可憑空 emit `.invalid<Field>`（Phase 1.i hardcoded infra case 只有 `invalidPayload` / `invalidDateFormat` / `aggregateNotFound` / `undefinedDomainError` / `serviceUnavailable`）。規則：先 grep `openapi.yaml` 的 `<A>ApiError` enum——若有 domain-specific `.invalid<Field>` case 則用之；**否則 fallback `.invalidPayload`**（保證 compile）。Date 走 `.invalidDateFormat`（infra case 保證存在）。

ISO8601 case 同 (Date.parseIso8601 + catch Iso8601ParsingError → `.invalidDateFormat`)。

### TODO fill category 3: DTO struct toDomain mapper body

**Before** (Phase 1.h scaffold)：
```swift
extension {DomainTypeName} {
    package init(from dto: {DtoTypeName}) throws {
        // TODO(/api skill): map fields with type conversion
        fatalError("TODO(/api skill): struct DTO toDomain for {DomainTypeName}")
    }
}
```

**After fill (simple 1:1 pass)**：
```swift
extension {DomainTypeName} {
    package init(from dto: {DtoTypeName}) throws {
{FIELD_ASSIGNMENTS}
    }
}
```

`{FIELD_ASSIGNMENTS}` per field：
- Simple pass: `        self.<name> = dto.<name>`
- Optional: `        self.<name> = dto.<name>`（type-system 自動處理）
- Decimal: `        guard let parsed = Decimal(string: dto.<name>) else { throw InvalidDecimalStringError(field: "<name>") }\n        self.<name> = parsed`
- Date: `        self.<name> = try Date.parseIso8601(dto.<name>)`（throws Iso8601ParsingError）
- Nested DTO with throwing init: `        self.<name> = try .init(from: dto.<name>)`

### TODO fill category 4: ApiComponents — **v1 NO-OP（audit H1）**

**v1 完全不動** `ApiComponents+<A>ApiError.swift` 的 switch。理由：

1. 此檔是 **aggregate-wide** error mapper，被同 aggregate 所有 UC 的 `mapToApiError` 共用。per-UC 把某 case 改成 `return nil` 會讓「目前 UC 不觸發、但同 aggregate 其他 UC 會觸發」的 domain error 從應回 **422** 變成 **503**（fall through to `serviceUnavailable`）——跨 UC 副作用。
2. unreachable 判定不可靠：`throw <A>Error.<case>` 可能來自 aggregate method、validator、helper、`ContextError(error:)` 間接 throw，單看 `<UC>Service.swift` body grep 抓不到。
3. Phase 1.i emit 的 `case .x: self = .x`（全 case 1:1）本身就 **compile-pass 且語意保守**（每個 domain error 都映射到對應 api error）——沒有「必須修正才能 build」的壓力。

**v1 行為**：skill 完全跳過 category 4，report 標記 `category 4: skipped (aggregate-wide, defer v2)`。

**defer v2**：aggregate-wide unreachable-case 精修（`return nil`）需要全 aggregate 所有 Service body 掃描 + `.ai/contexts/<Ctx>/<A>/api.md` 的 reachability allowlist 雙重證明才安全，屬獨立 task。

### Skill structure (6 steps, ≤200 LoC)

```
Phase 0: arg parsing + read-UC detection (lowercased prefix get/list/find) → exit 2
Phase 1: locate workspace + aggregate (glob <UC>Service.swift; 0 match → exit 1; >1 match across aggregates → exit 4 列候選)
Phase 2: prerequisite check (整套 scaffold + openapi.yaml + Service.swift + <A>Error.swift exist?) → exit 1; 存在但 corrupted → exit 4
Phase 3: parse inputs (AS Input struct + 欄位型別 + Service Input + payload schema 欄位存在性 + Error enum + ApiHandler method block + category 3 涉及時 domain type decl)
Phase 4: drift check (exit 3) + Variant A/B detection — 以 AS Input 欄位 Swift 型別為 truth (Decimal/Date/plain)
Phase 5: fill categories 1-3 (AS execute / handler asInput / DTO toDomain)；category 4 = skip (NO-OP)
         每 category 填前先驗 structural invariant 判斷已填/半填/未填 (見下方 idempotent 規則, audit M7)
Phase 6: report summary (filled / skipped-already / skipped-not-applicable / category-4-skipped) + warn unmapped fields
```

**Idempotent structural invariant (audit M7)** — 不靠「fatalError 消失」單一信號，每 category 定義「已完整填」的 structural 條件：

| category | 已完整填的判定 | 半填（→ exit 4） |
|---|---|---|
| 1 AS execute | body 含 `service.execute(` + 合法 `return .init(` 且無 `fatalError` | fatalError 消失但缺 `service.execute` 或 `return` |
| 2 handler asInput | 無 placeholder `_ = payload` 殘留 + 有完整 `let asInput = {UC}ApplicationServiceInput(` 直接構造（非 closure fatalError 形式） | fatalError 消失但 `_ = payload` 仍在或 asInput 仍 closure 形式 |
| 3 DTO toDomain | 每個 domain stored property 都有 `self.<f> =` assignment 且無 `fatalError` | fatalError 消失但缺 assignment |

符合「已完整填」→ skip 該 category；半填 → exit 4（要求 manual repair，不盲目覆寫）。
